### 1. Java 并发与 JUC

#### ConcurrentHashMap

- JDK 8 底层是数组 + 链表 + 红黑树。
- 空桶插入使用 CAS，而不是锁住整个 Map。
- 非空桶通常使用 `synchronized` 锁定桶头节点。
- 扩容时线程可以通过 `helpTransfer` 协助迁移。
- 元素计数使用 `baseCount` 和 `CounterCell` 降低竞争。

#### CAS

- CAS 表示比较并交换，包含内存位置、预期值和新值。
- 只有当当前值等于预期值时才更新，底层依赖 CPU 原子指令。
- 典型问题：ABA、高竞争下自旋消耗 CPU、单次通常只方便更新一个变量。
- ABA 可通过版本号或 `AtomicStampedReference` 解决。

#### volatile 与原子性

- `volatile` 保证可见性，并通过内存屏障限制相关指令重排。
- `volatile` 不保证复合操作的原子性。
- `count++` 包含读取、加一、写回，多线程可能丢失更新。
- 可使用 `synchronized`、`AtomicInteger.incrementAndGet()` 或显式锁保证安全。

#### ThreadPoolExecutor

七个参数:

```text
corePoolSize, maximumPoolSize, keepAliveTime, unit,
workQueue, threadFactory, handler
```

四种内置拒绝策略：

- `AbortPolicy`：抛出异常。
- `CallerRunsPolicy`：由提交任务的线程执行，可形成一定反压。
- `DiscardPolicy`：静默丢弃当前任务。
- `DiscardOldestPolicy`：丢弃队列中等待最久的任务，再尝试提交。

### 2. JVM

#### 运行时数据区

- 线程私有：程序计数器、Java 虚拟机栈、本地方法栈。
- 线程共享：堆、方法区；HotSpot 在 JDK 8 以后使用元空间实现方法区。
- 局部变量中的对象引用可位于当前线程的栈帧中，不能笼统地说“引用都是线程共享”。

#### 垃圾回收算法

- 标记-清除：简单，但会产生内存碎片。
- 标记-复制：无碎片、分配简单，但需要额外空间，存活对象多时复制成本高。
- 标记-整理：无碎片，但需要移动对象和更新引用。

### 3. Spring / Spring MVC

#### 依赖注入

- 构造器注入：依赖显式、可配合 `final`、方便测试，通常优先推荐。
- Setter 注入：适合可选依赖，但对象可能暂时不完整。
- 字段注入：代码简短，但依赖不显式，不利于单元测试。
- 字段注入不是通过 Setter 完成，不要混淆。

#### `@Transactional` 失效

- 同类内通过 `this` 调用，没有经过 Spring 代理。
- 对象由自己 `new` 出来，不受 IoC 容器管理。
- 方法不可被代理，如某些 `private` 或 `final` 场景。
- 异常被捕获后未重新抛出。
- 受检异常未配置 `rollbackFor`。
- 存储引擎不支持事务，或事务传播行为不符合预期。

#### Spring MVC 请求链路

```text
DispatcherServlet
  -> HandlerMapping
  -> HandlerAdapter（参数解析、类型转换、调用 Controller）
  -> Controller / Service
  -> HttpMessageConverter
  -> Jackson 序列化 JSON
  -> HTTP Response
```

#### Bean 作用域与线程安全

- 默认作用域是 `singleton`。
- 其他常见作用域：`prototype`、`request`、`session`、`application`。
- 单例 Bean 不天然线程安全；Controller/Service 通常应设计成无状态对象。

### 4. MySQL

#### ACID 

- 原子性：事务内操作全部成功，或全部回滚。
- 一致性：事务前后都满足数据库约束和业务规则；不是“一直读到事务开始时的值”。
- 隔离性：并发事务之间的影响受隔离级别控制。
- 持久性：事务提交后，宕机也不应丢失修改。

#### 隔离级别与并发异常

- 读未提交：可能出现脏读、不可重复读、幻读。
- 读已提交：解决脏读。
- 可重复读：解决不可重复读；InnoDB 默认级别。
- 串行化：隔离性最高，并发性能最低。
- 脏读：读到其他事务未提交的数据。
- 不可重复读：同一事务多次读同一行，结果不同。
- 幻读：同一条件多次查询，结果集行数或行集合变化。

#### InnoDB 索引

B+ 树优势：

- 非叶子节点主要保存键和子节点指针，单页扇出更大，树更矮，磁盘 I/O 更少。
- 叶子节点间通过链表连接，范围查询和排序遍历效率高。

聚簇索引与二级索引：

- 聚簇索引叶子节点保存完整行数据，一张表只有一个。
- 二级索引叶子节点保存索引列和主键值，而不是物理行地址。
- 聚簇索引选择顺序：显式主键 -> 第一个非空唯一索引 -> InnoDB 隐藏行 ID。

#### 慢 SQL 定位与 EXPLAIN

基本定位流程：

1. 通过慢查询日志、监控或 APM 确认慢 SQL、执行频率、耗时和扫描行数。
2. 使用 `EXPLAIN` 或 `EXPLAIN ANALYZE` 查看执行计划与实际执行情况。
3. 检查索引是否存在、是否符合最左前缀、是否因函数/隐式类型转换而失效。
4. 检查返回行数、回表、排序、分组、Join 顺序、锁等待和数据分布。
5. 修改 SQL 或索引后重新验证，并对比实际耗时与扫描行数。

`EXPLAIN` 重点字段：

- `type`：访问类型，常见顺序可概括为 `const > eq_ref > ref > range > index > ALL`；`ALL` 通常表示全表扫描。
- `possible_keys`：优化器认为可能使用的索引。
- `key`：实际选择的索引。
- `key_len`：实际使用的索引键长度，可用于辅助判断联合索引使用深度。
- `ref`：用什么值与索引比较。
- `rows`：优化器估算需要扫描的行数。
- `filtered`：条件过滤后预计保留的百分比。
- `Extra`：关注 `Using index`、`Using index condition`、`Using temporary`、`Using filesort` 等信息。

注意：不能只凭 `type` 或“有没有索引”下结论，还要结合数据量、选择性、实际耗时和业务访问模式。

#### 常见索引失效或未被选择的场景

- 联合索引没有满足最左前缀，例如索引 `(a, b, c)` 只查询 `b` 和 `c`。
- 在索引列上使用函数或表达式，例如 `WHERE YEAR(create_time) = 2026` 或 `WHERE age + 1 = 20`，且未建立可用的函数索引。
- 索引列与查询值类型不一致，发生隐式类型转换；是否失效需看被转换的一方。
- `LIKE '%keyword'` 或 `LIKE '%keyword%'` 以通配符开头，普通 B+ 树索引无法利用已知前缀定位。
- 联合索引中前面的列使用范围条件后，后续列通常不能继续确定索引扫描边界；但可能使用索引条件下推过滤。
- `OR` 连接的某个条件没有可用索引时，优化器可能选择全表扫描；需结合 index merge 和执行计划判断。
- 使用 `!=`、`<>`、`NOT IN`、`NOT LIKE` 等否定或低选择性条件时，优化器可能判断全表扫描更便宜，但并非必然失效。
- 查询返回大量数据，索引选择性很低，或回表成本过高时，优化器可能主动不使用索引。
- 统计信息过时或数据分布估算不准，可能使优化器选择不理想的执行计划。

应说“可能无法有效利用索引或优化器可能不选索引”，不要把所有场景都绝对化为“一定失效”；最终以 `EXPLAIN ANALYZE` 为准。

### 5. Redis

#### 布隆过滤器

- 由位数组和多个哈希函数组成。
- 写入时把多个哈希位置设为 `1`。
- 查询时任意一位为 `0` 则一定不存在；全为 `1` 只能说可能存在。
- 多个元素可共用同一个位，直接删除会制造假阴性；可使用计数布隆过滤器支持删除。

#### Redis 分布式锁

加锁基本命令：

```text
SET lock_key unique_value NX PX 30000
```

- `NX` 保证锁不存在时才加锁。
- `PX` 设置过期时间，避免客户端宕机后死锁。
- value 必须标识锁的持有者。
- 解锁时不能直接 `DEL`，否则可能删除别人在旧锁过期后新获得的锁。
- 需使用 Lua 脚本原子执行“比较 value + 删除 key”。

### 6. 操作系统：线程的共享与私有资源

同一进程内的线程通常共享：

- 进程的虚拟地址空间。
- 代码段、堆和全局/静态数据。
- 打开的文件、Socket 等进程级资源。

每个线程通常独享：

- 线程栈及其栈帧、局部变量。
- 程序计数器和 CPU 寄存器上下文。
- 线程 ID、调度状态等线程自身信息。

注意：“方法”不是线程私有资源，方法代码可被多个线程共同执行；每次方法调用产生的栈帧和局部变量才属于当前线程。堆中对象位于共享地址空间，但是否真的能被其他线程访问，还取决于对象引用是否被发布给其他线程。

### 7. HTTP / HTTPS

#### HTTP 方法与幂等性

- GET：获取资源，通常幂等。
- POST：创建资源或执行操作，通常不幂等。
- PUT：完整创建或替换指定资源，通常幂等。
- DELETE：删除资源，通常幂等。
- 幂等表示对同一资源执行一次或多次相同请求，服务器最终状态相同；响应码不一定相同。

#### HTTPS / TLS

- HTTPS 是运行在 TLS 加密通道上的 HTTP。
- 数字证书用来证明服务器身份，并绑定公钥。
- 非对称密码机制主要用于身份认证、签名验证和会话密钥协商。
- 对称加密用于握手后的高效业务数据传输。
- AEAD 等机制同时保护机密性和完整性。
