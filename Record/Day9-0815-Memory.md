## Memory：用户记忆与会话状态
```text
Memory 不是“把聊天都存下来”，应该按照聊天内容将聊天内容的作用方向、风险等方面

选择性的保存会改变未来决策而且可以被更正的信息


##  四层作用域模型
| 层级 | 作用域 | 典型内容 | 结束或读取边界 |
|---|---|---|---|
| Run / AgentState | 一次 Agent 运行 | currentStep、retryCount、pendingAction、stopReason | 为暂停恢复和本轮决策服务；运行结束后通常归档或过期 |
| Chat Memory | 当前会话的有效上下文 | 最近若干轮消息、会话摘要、当前话题 | 按 conversationId 隔离；只取当前生成需要的部分 |
| Chat History | 完整交互记录 | 全量用户消息、助手回复、时间与审计信息 | 用于展示、审计或分析；不等于每轮都送入模型 |
| Long-term Memory | 跨会话的用户或业务记忆 | 明确目标、稳定偏好、学习进度、经证据支持的薄弱点 | 按可信 userId 隔离；按需检索并允许更新、过期和删除

关键的边界
```text
questionId、pendingAction、retryCount 主要是 Run State，不应默认成为用户长期画像。
完整 Chat History 可以保存用于审计，但不应全部自动进入 Prompt。
“本轮答错 HashMap”是一次事件；“HashMap 持续薄弱”需要多次证据或明确评估后才能成为长期判断。
```

## 长期记忆

进行长期记忆的记录之前需要校准相关度内容
```text
1. Future value：它会改变未来的选题、解释或计划吗？
2. Evidence：来源是什么？是用户明确陈述、测验结果，还是模型猜测？
3. Sensitivity：业务是否真的需要保存？是否包含密码、令牌、身份证号等不必要敏感信息？
4. Lifetime：它是稳定事实、阶段状态，还是很快失效的一次性信息？
5. Correctability：能否追溯来源、更新旧值、响应用户删除或纠正？
```

一些相应的例子
场景 | 推荐处理 | 原因 |
|---|---|---|
| 用户明确说“以后只讲示例代码，不要求我实现” | 保存为长期学习偏好 | 明确、稳定、会改变后续教学 |
| 一道 HashMap 题答错 | 记为一次学习事件或待验证假设 | 单次证据不足以固化为长期薄弱点 |
| 三次独立练习都暴露同一误区 | 更新 WeaknessRecord | 证据重复且会影响后续选题 |
| 用户说“我下周面试”，面试结束后仍保留 | 设置 expiresAt 或届时重新确认 | 时间敏感，过期后会误导计划 |
| 用户更正“岗位改为 AI 应用开发” | 新值生效，旧值标记 SUPERSEDED | 不能让冲突记忆同时驱动决策 |
| 对话中出现密码或访问令牌 | 不写入长期记忆并避免日志泄露 | 无必要且风险高 |
| 模型推测用户“可能不擅长并发” | 不直接写 ACTIVE 记忆 | 推测不是已验证事实

## 读取与隔离规则
```text
1. userId 来自登录态或服务端可信上下文，不接受模型任意指定目标用户。
2. conversationId 只隔离会话，不能替代用户身份与授权。
3. 每次只读取当前任务相关的最小记忆，避免陈旧信息和上下文膨胀。
4. 冲突时优先用户明确更正、较新且证据更强的记录。
5. 记忆进入 Prompt 前仍需做权限、敏感性、状态和有效期检查。
6. 读取、写入、更新和删除都应记录 traceId、来源和操作者，敏感值要脱敏
```
